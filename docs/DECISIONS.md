# Architecture Decisions

## RBAC проверяется на двух уровнях

Права проверяются:

1. в интерфейсе — недоступные элементы скрываются;
2. в Server Actions — запрещённое действие невозможно вызвать напрямую.

Скрытие кнопки не считается достаточной защитой.

## Repository Pattern

SQL и работа с PostgreSQL находятся в repository-слое.

UI и Server Actions не должны содержать сложные SQL-запросы.

## Soft Delete

Для сущностей, связанных с историей работы, используется Soft Delete.

Причины:

- защита от случайной потери данных;
- возможность восстановления;
- сохранение связей;
- будущий журнал аудита.

Первым Soft Delete внедрён для Activities. Следующая сущность — Tasks.

## Модальное редактирование

Часто используемые сущности редактируются в модальном окне.

Причины:

- пользователь не теряет контекст списка;
- меньше переходов;
- быстрее ежедневная работа.

Полноценные страницы редактирования могут сохраняться как резервный маршрут.

## PostgreSQL pool

В приложении используется один глобальный экземпляр `Pool`.

Размер пула ограничен для небольшого VPS, чтобы не исчерпывать `max_connections`.

## Приоритет MVP

До внутреннего запуска разрабатываются только функции, необходимые сотрудникам для ежедневной работы.

Крупные интеграции, AI и расширенная аналитика откладываются до получения обратной связи от пилотной группы.
